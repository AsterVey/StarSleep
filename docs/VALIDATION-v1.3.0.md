## 同机性能观察

分别运行 v1.2.0 打包版和 v1.3.0 构建结果。每个状态在稳定后连续采样 3.2 秒；统计完整状态、时钟、预览 IPC 和应用持久化 fsync，并记录 Electron 进程指标。采样中没有任务到期。七天预览在 500 条计划下验证了每页 50 条及翻页。

| 计划数 | 可见 CPU 合计，1.2 → 1.3 | 工作集合计，1.2 → 1.3 | 新版迷你 CPU | 新版搜索耗时 |
| --- | --- | --- | --- | --- |
| 0 | 4.85% → 5.11% | 430 → 452 MiB | 0.66% | — |
| 1 | 5.19% → 6.20% | 437 → 432 MiB | 0.83% | 173 ms |
| 50 | 8.44% → 8.33% | 507 → 496 MiB | 1.41% | 303 ms |
| 500 | 8.88% → 8.40% | 508 → 489 MiB | 1.18% | 255 ms |

两版所有采样均为 **0 次闲置完整状态推送、0 次应用数据 fsync**。新版迷你采样也为 0 次完整状态推送与 fsync，且未新增窗口或改变渲染进程 PID；七天预览静置期间为 0 次预览推送。隐藏后时钟和完整状态停止发送，装饰停止状态生效；代码取消波纹绘制并暂停装饰动画。窗口位置只在交互结束或退出时保存，去重相同位置。

这些是短时观察，包含自动化与机器负载影响，不能当作功耗或长时间性能保证。部分小数据量下新版 CPU、内存上升。工作集为多进程相加，可能重复计入共享页面；搜索时间包含自动化通信与渲染等待。最后的退出位置保存修正不改变上述闲置采样路径。

## 打包版本与兼容

最终打包版验证了完整/迷你位置分别保存、从迷你退出后重启默认完整界面、置顶偏好保留、只有闹钟时的回退显示。模拟显示器范围变化会把屏幕外小窗校正回可见区域。主体验文件和备份同时损坏时保留原文件，既有计划继续有效。

使用同一专用测试目录，依次启动 v1.2.0、v1.3.0、再次 v1.3.0 和 v1.2.0；比较计划 ID、启用状态、绝对截止时间、下一次执行、全局暂停、handled 和 overrides。计划仍为存储版本 2。个人模板和互动偏好在新版重启后保留，旧版继续读取原计划。

## 安全边界与未执行项

- 所有自动化使用独立测试目录和 `--safe-mode`。旧功能回归实际等待一分钟，隐藏窗口后观察到“已拦截实际关机”日志，未调用 Windows 真实关机命令。
- 15 秒闹钟在隐藏状态按截止时间结束；最小化后托盘暂停也清理音源。完整退出结束测试进程。
- 未在用户当前安装上执行升级、卸载或覆盖真实数据。EXE 的构建与打包程序启动已验证；安装向导、桌面快捷方式和卸载需要独立人工安装验证。
- 未真实关闭电脑、睡眠唤醒、拔插显示器或修改系统时间。相关调度边界通过模拟时钟测试，显示器边界通过纯函数和模拟显示事件验证。
- 未测量电费、Token 用量或节能收益。没有联网素材、后台服务、自动启动或系统任务计划。

可重复运行：`npm test`、`npm run qa`、`npm run qa:regression`、`npm run qa:performance`、`npm run qa:upgrade`；打包后可运行 `node scripts/qa-window-v13.cjs`。回归输出目录可通过 `STARSLEEP_QA_OUTPUT=v13/regression` 单独指定。
